# History consent (draft)
Requires SaaS PR 193 and migration 108 before upgrading worker. Unknown policy blocks historical events and unscoped metadata, not explicit live events. Existing pending historical/unknown media entries remain on disk and are withheld in fresh mode; deletion/secure cleanup is a separate migration. No WhatsApp history deletion. Short consent cache is not an instantaneous revocation guarantee. Validate live message receipt, LID resolution, reconnect, label sync, backlog and Baileys history configuration before production. V6 and personal live-contact exclusions remain out of scope. Do not merge until coordinated E2E tests pass.

Private contacts draft: runtime policy includes owner-managed phone exclusions. Gate normalized inbound/outbound, mirror, media and sends. Unknown policy blocks all new contact capture/sends; this can drop new messages during outage and requires availability design and E2E before rollout. Existing queued payloads are withheld, not erased, and can replay after removing exclusions. Existing diagnostic events may still contain identifiers; no guarantee of zero processing. V6 not covered.

Operation modes: BUSINESS_ONLY restricts worker capture/send to explicitly approved numbers, MANUAL leaves non-private capture enabled and relies on SaaS AI-specific approval gates. Missing or malformed mode fields block capture. Requires SaaS 110 migration and coordinated rollout; tests pending.

## Explicit block spool cleanup (disabled by default)
V7_PRIVACY_SPOOL_PURGE_ENABLED=true enables atomic journal rewrites removing pending and delivered records for positively identified explicitly blocked phones, including media file removal by derived path. Unknown policy, unresolved numbers and business-only unapproved numbers are not purge instructions. Auth state, legacy media with no contactKey, receipt/retry memory, supervisor outbound spool, temporary files left by crashes, filesystem backups and V6 are not erased by this change. Enable only after E2E and operator review; no production cleanup performed.

Release hardening: queued sends fetch current policy after queue wait and before dispatch; malformed mode or consent cannot authorize history or contacts. This narrows but does not eliminate the post-check send race. Policy outages fail closed; staging must explicitly test recovery and availability, including OTP and owner notifications under business-only. No deployment.
